# 标准化交付要求评估：SJTU 笔记

评估日期：2026-10-18。参考：[交付机组数据要求](https://notes.sjtu.edu.cn/s/zzB-Iq_eRD)。网页读取成功；页面标注最后修改时间为 2026-10-17 05:28:16 UTC。本报告评估文档要求，没有读取目标求解程序源码。

## 判断与适用范围

该要求已经明确文件组织、字段名称、数组结构、主要单位、成本公式、初始条件、场景与部分边界规则，足以启动目标格式定义和少量试点转换。无需等全部公开库收集完再开始。

应将其定位为一个目标模型的交付规范：逐小时、系统总负荷、热电 UC、固定或冷热两档启动费用、负荷场景共用启停决策。现有网络、水电、多能、规划及随机研究包继续保留原件和源模型描述；转换是否等价需逐例判断。不能把全部 14 个来源组直接批量压缩进这些字段并宣称保留了原模型。

本次只完成格式评估和工作入口登记，没有创建正式 JSON Schema、转换器或标准化算例，没有启动 COPT/Gurobi 求解。

## 可直接采用的交付规则

| 要求 | 实施要点 |
|---|---|
| units.json、stochastic.json、provenance.json 与原始文件 | 三个 JSON 是每例交付接口；原始文件可采用版本固定的共享原件目录，独立发布包仍应带可追溯原件。仅有下载链接不能自动视为满足“交付原件” |
| 每字段一个机组数组 | 统一机组顺序，在 provenance 中保存下标与原始编号映射；明确下标从 0 还是 1 开始 |
| 逐小时、MW | horizon 为小时数；负荷长度匹配 horizon，机组数组长度匹配 n_units；导出数值必须有限 |
| 二次/一次/空载成本 | 按目标公式映射，明确原式的系数顺序、燃料热耗与价格、固定项是否已被计入 |
| 带符号初始持续时长 | 正为连续开机，负为连续停机；缺失不能填 0。尽量显式导出 initial_output |
| 确定性与随机统一入口 | 确定性为单场景、概率 1；场景负荷使用倍率或完整曲线之一；名称唯一，概率和按 1e-9 容差检查 |
| 比例备用 | 标量 reserve_fraction 只能等价表达各时段、各场景均满足同一负荷比例的备用要求 |
| 转换溯源 | 保存原始来源/版本/哈希、逐字段映射、换算、缺失与处理、不支持的约束、目标格式版本和转换器版本 |

目标 JSON 不允许 null；原始来源登记仍可用 null 表示未知。缺字段的来源应停留在待补充或不适用状态，不能为了通过目标结构检查用零或任意常数补齐。

## 必须处理的模型差异

1. **费用曲线。** PGLIB 的分段线性成本不能一般性地无损变成单一二次式。只有曲线本身能精确表示时才标记等价；拟合需另建派生实例，保存原曲线、拟合区间/方法、误差及非负系数等约束。拟合误差验收阈值仍需在规范中确定，不能默认为零误差。
2. **启动费用。** 固定费可直接映射；冷热两档要核对严格大于阈值的定义、初始停机历史及整数时间边界。多档或指数曲线若简化，须记录其对目标函数的改变。个别原阈值未必能在冷启动附加小时非负条件下表达。
3. **普通爬坡在启停时仍生效。** 原模型若启动/停机时放松普通爬坡，原参数直接照搬会改变可行域。pstart/pshut 是出力加备用上限，不应直接替代 ramp_up/ramp_down；具体不等式与索引还应通过目标程序核对。
4. **最小开停机至少一小时。** 原件允许零值、非整数时长或不同取整规则时，不能直接改为 1 或向上取整并称为等价。应记录为不兼容或独立派生处理。
5. **15 分钟转小时。** 功率负荷通常涉及按时间加权的小时平均；能量、爬坡、最小持续时间、初始历史和启停次数需分别处理。每次启动/停机费用不能按时段数统一乘除。聚合还可能丢失小时内峰值与启停行为，不能只调整数组长度。
6. **初末边界。** 目标模型末小时禁止停机、时域末端截断最小开停机约束。即使字段数值不变，与原模型边界不同也需登记；不能据总成本接近判断复现成功。
7. **网络和其他设备。** 节点负荷汇总会失去线路、节点及 N−1 约束；水电水量、储能状态、可调弃风弃光、时变可用容量和故障等没有对应接口。新能源扣减为净负荷还需处理负净负荷与弃电语义。此类简化只能作为派生算例。
8. **随机信息结构。** 目标格式对应全天共用启停、分场景出力与备用，不能自然代表多阶段启停或任意风光/故障场景。只有信息结构与场景内容均匹配时才视为等价转换。

## 建议补足的规范信息

- 给交付规范固定版本号，并记录参考页面日期/指纹；页面后续改动需重新评估，不能无记录覆盖格式。
- 明确货币统一是每例内部还是整个集合；至少记录 currency、价格年份（未知则在元数据标缺失），跨币种转换保存汇率来源和日期。
- provenance 明确单位表、数组下标约定、成本是否已含空载项、原模型/目标模型边界差异。
- 将转换状态标为等价映射、派生简化或不适用/待补充；将结构检查、模型语义审查、求解和独立验解分开记录。
- 确认目标程序实现的变量含义、备用在爬坡/启停限制中的位置、时段索引，以及启停时间边界与文档一致。文档明确的要求足够先编写格式规范，但不能据此宣称实际读取器已经兼容。

## 建议启动顺序

1. 固化该目标交付格式的字段字典、JSON Schema 与 provenance 模板；保留原始归档和未来网络/水电等扩展接口的资料。
2. 从现有原件中筛选参数完整、线性或二次成本、固定启动费用、无网络的小算例，先做 1—3 个试点。候选可从 OR-LIB 相关原件等开始审查；此处未确认某一具体文件能无损转换，许可也需逐例核对。
3. 完成结构、长度、单位、映射与边界审查，形成每例转换报告。此类检查是标准化的必要验收，应与之前“采集时不验证”区分。
4. 再以 PGLIB 分段成本等作为有损转换/不支持报告的对照，明确误差与派生身份，避免直接批量转换 56 例。
5. 试点通过后批量处理兼容子集。COPT/Gurobi 建模、可行性与基准结果仍另行开展，不与格式转换完成混写。

结论：现在具备启动小批标准化的资料基础，首要工作是落实此目标格式及源字段映射；全库统一转换与模型复现仍需分层推进。
